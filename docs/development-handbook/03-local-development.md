# Local development

## Prepare and preview

Inspect the repository's branch, status, and current commit before editing. Work on a topic branch from updated `master`, keeping unrelated local edits intact. This baseline has no package manifest, dependency lockfile, build command, or framework CLI. Do not run `npm install` as a default step; it would add machinery the site does not use.

Use a native static server from the repository root:

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

Open `http://127.0.0.1:4173/`. This is a maintenance preview command for the static files, not a repository-provided application daemon. If Python is unavailable on NixOS, enter a temporary Nix environment containing Python 3 rather than installing a global runtime or adding a container. The repository has no pinned Nix flake, so full reproducibility and production-host qualification remain gaps.

The server must run from the directory containing `index.html`; otherwise relative assets may return 404 or you may see a directory listing. Check the terminal's requests and browser Network panel. The application needs no secret values or environment variables. Port 4173 is a preview choice and can be changed if occupied.

## Local evidence to collect

Because there is no automated suite, a content or interface change needs a deliberate local inspection. Load the page at desktop and narrow phone widths. Check that the header, about section, work examples, and contact actions are reachable. Use keyboard navigation to reach slideshow controls. Inspect the console for exceptions and Network panel for missing images. Advance through all slides and wrap in both directions.

Set reduced motion through the browser or operating system and reload; automatic rotation should stop while controls still work. Do not actually submit an appointment or send a message as a casual test. Validate the destination URL and use an approved non-production verification path if completion must be tested.

These observations are not generated by a build. Record the actual browser and tested viewports in the PR. If adding automated checks later, use a small tool appropriate to static HTML and browser behavior; avoid introducing a large application runtime merely to validate links.

## Publishing boundary

The repository does not define a complete deployment pipeline. A local HTTP preview does not prove HTTPS, cache headers, redirects, domain records, or the live host's behavior. Keep deployment credentials outside the repo. Push a reviewed topic branch and open a PR against `master`; human merge and release remain separate actions. Preserve deployment workflows if added later, while keeping routine hosted CI disabled unless explicitly authorized.
